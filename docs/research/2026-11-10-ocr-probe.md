# OCR probe for screen waits (2026-11-10)

This probe opens run 2 of the live-interaction outcome. It settles two points that
[`docs/plans/live-interaction-design.md`](../plans/live-interaction-design.md) left to it: the OCR engine for
`screen_text`, and the change threshold and duration for `screen_settled`.

## Recommendations

- Use `ocrs` as the engine, pinned to 0.12.x (0.12.2 with `rten` 0.24.0). It read 31 of 44 key strings exactly and
  11 more with a one- or two-character error. Tesseract read 21 exactly and missed 19 outright. On full frames,
  Tesseract missed the strings an agent waits for in a graphical installer: every button label and every highlighted
  list row. `ocrs` 0.12.2 builds on Rust 1.89 and passes `cargo deny check advisories`; later releases need Rust 1.94.
- Invert a frame or region whose mean luminance is below 0.5 before OCR. `ocrs` misreads light-on-black console
  fonts, and inversion fixed most of those misreads.
- For `screen_settled`, compare pixels by exact equality, and treat a screen as settled when no consecutive pair of
  frames 500 ms apart changes more than 600 pixels (0.06 % of a 1280x800 frame) for 3 s. Idle noise reached 415
  pixels; the smallest real change other than typing was 1145 pixels.

## Set-up

The host has an Intel Core Ultra 7 255HX with 20 threads. `trial-deb13` was running during all timings.

- `ocrs`: a throwaway binary in `/tmp`, built with `cargo +1.89 build --release` against `ocrs = "=0.12.2"`,
  `rten = "=0.24.0"` and the repository's `image` features (`png`, `pnm`). It loads both models once, then times
  `prepare_input`, `detect_words`, `find_text_lines` and `recognize_text` over 5 runs and reports the median. A
  region is cropped from the full-resolution frame first. Model loading took about 8 ms and is excluded.
- Tesseract: 5.5.0 with Leptonica 1.84.1 and the `eng` model, from `apt-get install tesseract-ocr` in the
  official `docker.io/library/debian:trixie` image under rootless Podman 5.7.0. The default page segmentation
  (`--psm 3`) was used. Each timing is the median of 5 `tesseract <file> stdout` runs inside the container, so it
  includes process start and model load: about 54 ms on a 16x16 blank image. An in-process binding would save that.
- Frames: `virsh -c qemu:///system screenshot`. libvirt returned PNG here, although the file was named `.ppm`;
  `src/display.rs` already picks the decoder from the MIME type `virDomainScreenshot` returns. One capture through
  the `virsh` CLI took 0.17 to 0.19 s.

Over the 44 full-frame key strings, `ocrs` read 31 exactly, 11 near and missed 2. Tesseract read 21 exactly, 4 near
and missed 19.

Tesseract's misses follow two patterns. It drops highlighted rows, which are light text on a dark bar, and it drops
button labels. On the full Windows frames it also loses most of the dialog body, keeping the window title and the
page heading, plus `English (Un` twice on the language page. These held under
`--psm 11`, under a 2x upscale with grayscale, and under inversion. Only a tight crop around the highlighted GRUB entry
(380x26) made it read "Graphical install". A crop recovered the Windows dialog text but not "Next" or "Continue".

`ocrs` misreads light-on-black monospace text: confusions such as `l`/`1`/`I`, `y`/`u` and `6`/`0`, dropped trailing
dots, and spaces inserted inside words (`opt ions`). On the 400x80 console crop, it split the two lines into scattered
single words. Inverting the image to dark-on-light changed this:

- the console crop read both lines exactly (`Debian GNU/Linux 13 trial-deb13 tty1`, `trial-deb13 login:`);
- the full console frame read `trial-deb13` exactly, with `ttu1` and `log in:` still near;
- the VGA screen read the machine UUID and the SeaBIOS version string exactly, and `SeaBI0S` near;
- on the GRUB menu (mean luminance 0.30) it fixed `13.7.0`, `Installer` and `GRUB Command line`, and broke `UEFI`
  (`UEFT`) and `Select` (`Selert`).

The console frame's mean luminance is 0.001, and the light installer screens' is 0.88. A cut-off at 0.5 inverts the
console and GRUB frames and leaves the GUI screens alone. Upscaling by 2x or 3x with nearest-neighbour made `ocrs`
worse on both console screens, so OCR should run at native resolution.

## Build, MSRV and `cargo deny`

The check added the dependency to an export of the repository (`git archive HEAD`) in `/tmp`, with `CARGO_TARGET_DIR`
there too.

- `cargo +1.89 add ocrs@=0.12.2 rten@0.24.0` and `cargo +1.89 build` succeeded. The lock file gained 24 crates:
  `ocrs`, nine `rten*` crates, `rayon`, `rayon-core`, three `crossbeam-*` crates, `either`, `flatbuffers`,
  `hermit-abi`, `num_cpus`, `rustc-hash`, `rustc_version`, `semver` and `typeid`.
- `rten` 0.24.0 and `rten-simd` 0.24.0 declare `rust-version = "1.89.0"`. Every `rten` release from 0.25.0 declares
  1.94.0. `ocrs` 0.13.1 depends on `rten` 0.26 and 0.14.0 on `rten` 0.28, so `ocrs` 0.12.2 is the latest release that
  builds on 1.89.
- `ocrs` declares no `rust-version`, so the MSRV-aware resolver does not hold it back: a plain `cargo +1.89 add ocrs`
  picked 0.14.0, and the build then failed with "rten@0.28.0 requires rustc 1.94.0". The dependency must be pinned
  (`ocrs = "~0.12.2"`, `rten = "~0.24.0"`).
- `cargo deny check advisories` (cargo-deny 0.20.2) printed `advisories ok`.
- `cargo deny check licenses` cannot judge the change: the repository has no `deny.toml`, and the default
  configuration allows no license, so it rejects every crate, the existing ones too. By `cargo metadata`, every added
  crate is `MIT OR Apache-2.0` except `flatbuffers` 24.12.23, which is `Apache-2.0` only. The lock file already holds
  Apache-2.0-only crates (`rmcp`, `rmcp-macros`, `sync_wrapper`), so the addition brings no new kind of license.

## Models

`ocrs` needs a detection and a recognition model. No checksums for them are published. The `ocrs` README and
`ocrs/examples/download-models.sh` at tag `ocrs-v0.12.2` point at the `.rten` files, which `ocrs-cli` 0.12.2 also
names as its defaults. Both URLs now return HTTP 403. At tag `ocrs-v0.14.0`, the script fetches `.onnx` files from the
same bucket, and those still download. `rten` loads ONNX directly from 0.23 on, and 0.24.0 enables its `onnx_format`
feature by default. `ocrs` 0.12.2 ran every result above with these ONNX models.

Both files sit under `https://ocrs-models.s3-accelerate.amazonaws.com/`:

## Screen change

`probe diff` counted, for each pair of consecutive frames, the pixels where any RGB channel differs by more than a
tolerance. Tolerances 0 and 8 gave identical counts on the idle hostname entry, and 0, 8 and 32 on the GRUB highlight
move. On the progress screen, tolerance 8 dropped up to 6 % of the changed pixels, at the anti-aliased edges of the
text. A screenshot is a lossless copy of the framebuffer, so exact equality is enough.

### Threshold and duration

A threshold between the busy spinner (415 pixels) and the smallest progress step (1145 pixels) separates idle noise
from progress. 600 pixels sits between them, and is 0.059 % of a 1280x800 frame. The cursor blink, at 15 to 16
pixels, is far below it.

The threshold is best stated in changed pixels, not as a share. Cursors, spinners and glyphs have a fixed size in
pixels whatever the resolution. The same 415-pixel spinner is 0.086 % of an 800x600 frame, above a 0.059 % share.
In a 300x40 region it is 3.5 %. If the design keeps a share, it should be a share of the full frame, also for a
region, so that the measurements above still apply.

A typed character, at 70 pixels, falls below the threshold, so `screen_settled` does not see typing as change. An
agent that types knows it did; a `screen_text` wait on the entry checks the result. A threshold low enough to catch one
character would also stop at every spinner frame.

A settle duration of 3 s outlasts the 2.5 s mid-progress stall seen here, while page changes completed in under 0.5 s.
Callers that know a screen stalls longer can pass a longer duration.

## Downloads and volumes

Two volumes in `agent-vms` now hold the installer ISOs:

- `tpl-debian13-netinst.iso`, from `debian-13.7.0-amd64-netinst.iso`, 792,723,456 bytes, SHA-256
  `a7ef94ac2fb9a7fec454552abd629b7cc9d5155c886165a45649f5ce6167e355`.
- `tpl-win11-26h2.iso`, from `~/Downloads/en-us_windows_11_business_editions_version_26h2_x64_dvd_16357792.iso`,
  8,921,073,664 bytes, SHA-256 `9a9428dcf8ad48391744ac63062619e05758230fe4e9c9753515d413cfc316bb`.

Their provenance and upload:

- The netinst ISO came from `https://cdimage.debian.org/debian-cd/current/amd64/iso-cd/` and matched that directory's
  `SHA256SUMS`. `gpgv` verified `SHA256SUMS.sign` as a good signature by "Debian CD signing key", fingerprint
  `DF9B9C49EAA9298432589D76DA87E80D6294BE9B`, made on 12 September 2026. The keyring was
  `/usr/share/keyrings/debian-role-keys.gpg` from `debian-keyring` 2025.07.26, installed in the trixie container.
- Microsoft publishes no checksum for the Windows file that can be fetched without signing in. The sum above is the
  local file's, as it was.
- Both volumes were made with `virsh vol-create-as … --format raw` at the file's exact size and filled with
  `virsh vol-upload`. Reading each back matched the source.

`virsh vol-download` to `/dev/stdout` gave the volume's bytes plus a trailing newline in one read, so the sum taken
from that pipe was wrong. A later read of the template `tpl-debian13.qcow2` through a pipe gave exactly the file's 696778752
bytes, and dropping the last byte then gave a wrong sum. The pipe's output is therefore not reliable for a sum:
download to a file and hash the file.

## What this changes in the design

- The engine stays `ocrs`, as the design proposed, but pinned to 0.12.x. Moving to a later release means raising the
  repository's `rust-version` to 1.94.
- `scripts/fetch-ocr-models.sh` must fetch the `.onnx` files, because the `.rten` files the `ocrs` 0.12.2 README
  names are gone, and pin the SHA-256 sums above.
- Risk 1 holds for `ocrs` on console text. Inverting dark frames reduces it, and loose patterns still help: `ocrs`
  drops trailing dots and can split a word with a space.
- A run-2 case that waits for a GRUB menu on the display needs a VM whose GRUB draws on the display. `trial-deb13`
  sends its menu to the serial line; the netinst ISO under UEFI draws one.
- `screen_settled` needs a threshold in pixels (600 by default), or a share of the full frame, rather than a share of
  the region.
